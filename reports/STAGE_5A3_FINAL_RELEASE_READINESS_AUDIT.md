## 1. Executive Summary

This Stage 5A.3 audit evaluates the local **VP52** monorepo (`client/`, `client/android/`, and `server/`) after completion of Stages 1 through 5A.2 to determine whether the codebase is ready for controlled production deployment and Google Play Store promotion.

Across Parts A–H:
- **What passed cleanly:** Client-side centralized API parsing ([`parseApiResponse`](file:///Users/sarthaklabhade/FREELANCING/5257/client/src/utils/apiResponse.js)), authenticated Bearer CSV exports ([`downloadAuthenticatedCsv`](file:///Users/sarthaklabhade/FREELANCING/5257/client/src/utils/csvExport.js)), media URL resolution ([`resolveMediaUrl`](file:///Users/sarthaklabhade/FREELANCING/5257/client/src/utils/api.js#L112-L128)), client-side image compression on all 5 uploaders, customer coin displays having zero `₹`/rupee values, backend `better-sqlite3` 13.1.1 + Node `>=22` engine alignment, graceful shutdown, Google ID-token verification hardening ([`googleOAuth.js`](file:///Users/sarthaklabhade/FREELANCING/5257/server/utils/googleOAuth.js)), and **11 offline/isolated backend test suites** passed inside an isolated scratch copy without touching `server/db/rewards.db`.
- **What blocks release:** Inspection uncovered **2 CRITICAL authentication/authorization vulnerabilities** (an unguarded hardcoded demo OTP + arbitrary 6-character OTP acceptance on merchant login, and unrestricted `role: 'shop'` API access issued to pending self-registered merchants), **several HIGH security gaps** (unprotected legacy admin routes missing `requirePermission`, missing rate limiters on admin/merchant/upload/OTP/deletion endpoints, deactivated admin token acceptance, and weak upload validation), **a systemic HIGH UI defect** where stripping `₹` removed currency indicators from real-world cash prices/bills/revenues alongside coin/point terminology drift, and **4 HIGH Android/Play Store blockers** (`versionCode 2` not incremented, Google AdMob test IDs in manifest/JS, dev bundle `http://10.0.2.2:5000` still synced in Android assets, and global cleartext/mixed-content settings).

### Epistemic Classification Legend Used in This Report
- **[Verified Fact]**: Directly observed via command execution, file reads, OpenSSL inspection, checksums, or executed automated test output in this audit.
- **[Static Observation]**: Observed by reading source/config code that was not executed end-to-end in a live runtime or browser session.
- **[Inference]**: Security, operational, or UX conclusion logically derived from Verified Facts and Static Observations.
- **[Not Tested]**: Flows or environments intentionally excluded or blocked (live VPS/Nginx, physical Android handsets, Playwright/real-browser E2E, TCP-binding suites blocked by the sandbox).

## 2. Overall Verdict

### **`NOT READY`**

**Summary Justification:**  
Deploying or publishing the current local build to production or Google Play is blocked by:
1. **Two CRITICAL exploitable authentication/authorization flaws** allowing arbitrary takeover of active merchant accounts via `/api/auth/shop/login-mobile` (`123456` or any 6-character string) and allowing unapproved (`status = 'pending'`) or suspended merchants to call operational billing/redemption/QR/product APIs.
2. **HIGH backend authorization, rate-limiting, and upload-validation gaps** across legacy `/api/admin/*` routes, `admin/login`, `upload.js`, and OTP/auth endpoints.
3. **HIGH UI currency ambiguity** where genuine INR financial figures (bills, prices, revenues, refunds, max discounts) render as unitless numbers across Customer, Merchant, and Admin screens.
4. **HIGH Android & Play Store release blockers** (`versionCode 2`, AdMob test IDs, development `10.0.2.2` Capacitor assets still bundled inside `client/android/app/src/main/assets/`, and `usesCleartextTraffic="true"` + `MIXED_CONTENT_ALWAYS_ALLOW`).

No production VPS deployment, database migration, `.aab` Play Console upload, or APK release should proceed until a remediation stage (**Stage 5B**) resolves all Critical and High blockers and re-verifies them.
